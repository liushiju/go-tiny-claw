# go-tiny-claw

一个用 Go 实现的轻量级 Agent Engine 骨架项目。当前仓库还处在架构搭建阶段，目标是逐步把大模型 Provider、工具系统、上下文管理和执行引擎拼装成一个可运行的智能体框架。

## 当前状态

目前项目已经完成：

- Go 模块初始化
- 命令入口 `cmd/claw/main.go`
- Agent 核心分层的目录预留
- 启动日志与整体架构蓝图说明

当前还没有完成：

- 实际的模型 Provider 接入
- Tool Registry 与工具执行能力
- 上下文 / Memory 管理
- 任务编排与 Engine 运行逻辑

换句话说，这个仓库现在更像是一个“Agent 系统脚手架”，而不是一个可直接投入使用的完整产品。

## 设计目标

`go-tiny-claw` 试图把一个智能体系统拆成几个清晰模块：

- `provider`
  负责连接大模型，充当系统的“大脑”。
- `tools`
  负责注册和调用外部工具，充当系统的“手脚”。
- `context` / `memory`
  负责上下文与记忆管理，决定系统“记住什么”。
- `engine`
  负责调度各模块，驱动任务执行。

这种拆分方式适合后续逐步演进，比如替换模型供应商、扩展工具链、引入短期/长期记忆等。

## 快速开始

### 环境要求

- Go 1.25.2 或更高版本

### 运行项目

```bash
go run ./cmd/claw
```

```text
2026/04/22 18:11:43 架构蓝图搭建完毕，等待各核心模块注入！
```

## 项目结构

```text
.
├── cmd/
│   └── claw/
│       └── main.go
├── internal/
│   ├── context/
│   ├── engine/
│   ├── feishu/
│   ├── memory/
│   ├── provider/
│   └── tools/
└── go.mod
```

目录说明：

- `cmd/claw`
  程序入口，负责组装并启动应用。
- `internal/provider`
  预留给模型接入层，例如 Claude、OpenAI 或其他 Provider。
- `internal/tools`
  预留给工具注册与执行系统，例如 Bash、文件读写、HTTP 调用等。
- `internal/context`
  预留给任务上下文管理。
- `internal/memory`
  预留给记忆模块。
- `internal/engine`
  预留给 Agent 的核心调度逻辑。
- `internal/feishu`
  预留给飞书相关集成。

## 当前入口逻辑

`cmd/claw/main.go` 目前主要表达了后续的初始化顺序：

1. 初始化模型 Provider
2. 初始化 Tool Registry
3. 初始化上下文管理器
4. 组装并启动核心 Engine

这部分现在还以注释和占位代码为主，说明架构方向已经确定，但功能实现尚未开始展开。

## 开发路线图

建议按下面顺序推进：

1. 定义 `provider` 抽象接口，并先接入一个最小可用模型实现
2. 定义 `tool` 接口与注册机制，先完成基础工具如 `bash` / `file`
3. 建立 `engine` 的任务循环，串起模型推理与工具调用
4. 增加 `context` 和 `memory`，让系统具备连续对话与状态管理能力
5. 补充测试、配置管理和可观测性
